个人博客出现的问题及解决

2026年7月29日，我花了大半天时间，只为把第二篇文章发布到博客上。从404到首页不显示，从文件丢失到网络超时，这篇文章记录了我遇到的所有问题和解决办法

一、坑一：文章发布后，首页不显示

*问题现象： 执行完 hugo 和 git push 后，访问博客首页，只能看到第一篇文章，第二篇文章没有出现 *排查过程： 第一步，检查 content/posts/ 文件夹里是否有第二篇文章的文件

ls content/posts/

文件存在，说明没有丢失

第二步，检查文章的 draft 状态

notepad content/posts/build-blog-notes.md

查看文件开头的 draft 字段（如果是 true，Hugo 就不会生成它，必须改成 false）但是已经被我改成false了，这里没问题

第三步，检查 public/posts/ 文件夹

ls public/posts/

（如果没有第二篇文章对应的文件夹，说明 hugo 命令没有正确生成它）显示找不到该文件夹

*解决办法： 确保 draft: false 后，重新执行：

hugo --minify --cleanDestinationDir

然后再检查 public/posts/，才确认生成了文章文件夹

二、坑二：主题文件夹丢失 *问题现象： 执行 hugo 时，报错说找不到布局文件

WARN found no layout file for "html" for kind "home"

*原因分析： themes/PaperMod 文件夹被清空或不存在了，我怀疑是在 main 分支和 gh-pages 分支之间切换时，文件被覆盖或丢失了

*解决办法： 重新把主题文件夹放回 themes/ 目录 第一步，确认主题文件夹是否存在

ls themes

发现 PaperMod 是空的，又需要把它重新放进去

第二步，从 GitHub 下载主题 ZIP 包 访问：https://github.com/adityatelange/hugo-PaperMod/archive/refs/heads/master.zip

第三步，解压后重命名为 PaperMod，复制到 my-blog/themes/ 里面

第四步，确认主题已就位

ls themes\PaperMod\layouts

可以看到 _default、_partials、_shortcodes 等文件夹就OK的

三、坑三：点击文章链接出现 404 *问题现象： 首页显示了两篇文章的标题，但点击任意一篇文章，都跳转到 404 页面

*原因分析： hugo.toml 里的 baseURL 写错了。我的 GitHub Pages 地址是 daylily-7.github.io，但配置里写的是 Daylily.github.io

*解决办法：

打开 hugo.toml，把第一行改成正确的地址

baseURL = "https://daylily-7.github.io/"

修改后重新生成并部署：

hugo --minify --cleanDestinationDir

然后重新推送

注意：我这样改完之后反而变成全站 404，应该是 gh-pages 分支被覆盖了，要重新部署一次

四、坑四：配置文件 hugo.toml 经常消失

*问题现象： 明明刚创建了 hugo.toml，执行 hugo 时却报错找不到配置文件

ERROR Unable to locate config file

*原因分析： hugo.toml 属于 main 分支（源码分支），而 gh-pages 分支只存放生成的网页文件，当执行 git checkout gh-pages 时，工作目录切换到了 gh-pages 分支的内容，此时hugo.toml 自然就消失了，切回 main 分支才会回来

*解决办法： 确认当前分支，切回 main

git branch
git checkout main

然后重新创建 hugo.toml（发现确实丢了

notepad hugo.toml

把配置内容粘贴进去，保存

五、坑五：git push 网络超时 *问题现象： 执行 git push origin main 时，报错：

fatal: unable to access 'https://github.com/...': Failed to connect to github.com:443

*原因分析： GitHub 在国内访问不稳定，网络连接经常被重置

*解决办法： 方案一：多试几次

git push origin main

连续尝试 3-5 次，有时候重试就能成功（我通过反复尝试成功了）

方案二：换用 SSH 方式

git remote set-url origin git@github.com:Daylily-7/Daylily-7.github.io.git
git push origin main

六、总结最终成功部署的完整流程： 第一步，确认在 main 分支

git checkout main

第二步，确认主题和配置文件都存在

ls themes\PaperMod\layouts
ls hugo.toml

第三步，生成网站文件

hugo --minify --cleanDestinationDir

第四步，删除旧的 docs 文件夹，用 public 替换

Remove-Item -Recurse -Force docs
Move-Item -Path public -Destination docs

第五步，添加到 Git 并推送

git add docs/
git commit -m "更新博客"
git push origin main

第六步，等待 1-2 分钟，刷新博客

https://daylily-7.github.io

七、关于 gh-pages 和 docs 的选择

一开始我用了 gh-pages 分支来部署，但反复出现 404 和各种问题。后来我改用了 docs 文件夹方式（把网站文件放在 main 分支的 docs 文件夹里），然后在 GitHub Pages 设置中把分支指向 main、文件夹指向 /docs

这种方式更稳定，不容易出现分支切换导致文件丢失的问题

八、经验总结

1.遇到 404 先检查 baseURL 是否正确

2.主题文件丢失是常见问题，尤其是在分支切换后，记得重新确认themes/PaperMod/layouts 是否存在

3.hugo.toml 配置文件只存在于 main 分支，切到 gh-pages 分支后是看不到的，这是正常的。

4.git push 网络超时是 GitHub 在国内的常态，多试几次或换 SSH 方式

5.部署前一定要检查 public/posts/ 里是否生成了文章对应的文件夹

九、为什么我之前会出问题以及如何避免

*我的问题根源：分支切换导致文件混乱

我的博客仓库有两个主要分支：

  • main 分支：存放原材料（文章 Markdown 文件、主题、配置文件 hugo.toml）
  • gh-pages 分支：存放成品（hugo 生成的 HTML 网页文件）

我之前发布文章的流程是这样的：

  1. 在 main 分支写文章，执行 hugo（生成 public 文件夹）
  2. 切换到 gh-pages 分支，把 public 里的文件复制过去
  3. 切回 main 分支修改配置
  4. 又切到 gh-pages 分支……

来回切换几次后，Git 会提示文件冲突，拒绝切换。然后我执行了 git rm -rf . 强行清空，结果把当前分支的所有文件都删了

最终结果：main 分支的原材料被清空，gh-pages 分支的成品也不完整，主页自然就 404 了

*我现在用的方式：单分支 + docs 文件夹

为了避免分支切换导致的问题，我现在改用更稳定的方式：

  • 永远在 main 分支工作
  • 生成的成品放在 docs 文件夹里（而不是另一个分支）
  • git push 把原材料和成品一起推上去

这样就不存在“来回切换导致文件丢失”的问题了。

十、标准发布流程

第一步：确认在 main 分支

git checkout main

第二步：写文章

hugo new content posts/文章名.md

注意：文章名建议用英文，比如 my-third-post.md，避免中文编码问题

第三步：编辑文章

notepad content/posts/文章名.md

做两件事：

  1. 把 draft: true 改成 draft: false
  2. 在 --- 下方写正文

保存并关闭

第四步：检查主题是否存在（防止主题丢失）

ls themes\PaperMod\layouts

如果提示找不到路径，说明主题丢了。把 PaperMod 文件夹重新复制到 themes\ 里。

第五步：生成网站文件

hugo --minify --cleanDestinationDir

看输出结果里的 Pages 数量，应该是 8 或 11 个左右。如果只有 5 个，说明主题没加载上，回到第四步

第六步：替换 docs 文件夹

Remove-Item -Recurse -Force docs
Move-Item -Path public -Destination docs

第七步：提交并推送

git add docs/
git commit -m "发布新文章"
git push origin main

看输出里有没有 main -> main，如果有，说明推送成功了

第八步：刷新博客

等待 1-2 分钟，访问 https://你的用户名.github.io，按 Ctrl + F5 强制刷新

hugo --minify --cleanDestinationDir
